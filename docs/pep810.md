# PEP 810 and `__lazy_modules__`

[PEP 810](https://peps.python.org/pep-0810/), "Explicit Lazy Imports", was
accepted by the Python Steering Council on 2025-11-03 and ships in Python
3.15. It adds `lazy` as a soft keyword in front of an import statement:

```python
lazy import json
lazy from pathlib import Path
```

The import only actually runs the first time `json` or `Path` is used, not
at module load time. Unlike the earlier, rejected PEP 690, this is explicit
and per-statement rather than implicit and global — you opt in one
statement at a time, and only at module level.

## The pre-3.15 fallback: `__lazy_modules__`

PEP 810 also defines a forward-compatibility marker for projects that can't
require 3.15 yet:

```python
__lazy_modules__ = ["expensive_module", "expensive_module_2"]
import expensive_module
```

On interpreters older than 3.15, `__lazy_modules__` is inert — the import
still runs eagerly. It exists so a codebase can declare which imports are
*intended* to be lazy ahead of a 3.15 upgrade, without breaking on older
interpreters in the meantime.

lazy-fix uses this as its own fallback: when a project's `requires-python`
doesn't allow 3.15+, `fix` inserts or updates a `__lazy_modules__` list
instead of emitting `lazy import` syntax, and `check` verifies that list is
present and accurate rather than checking for the syntax itself.
